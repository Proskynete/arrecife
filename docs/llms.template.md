# @eduardoalvarez/arrecife

> GENERATED by `scripts/build-llms.mjs`. Do not edit by hand: the prose lives in
> `docs/llms.template.md` and the inventory comes out of the types on every
> build. `pnpm check:llms` fails if this file and the code stop saying the same
> thing.

The component library of Eduardo Álvarez's visual identity. React 19,
TypeScript, Tailwind v4, shadcn/ui on top of Radix.

This document is for an agent writing code in a project that consumes the
library. If you are working **inside** the Arrecife repo, the document is
`AGENTS.md`, not this one.

## First things first: do not reimplement what is already here

Before writing a card, a button, a header or a footer, look through the inventory
below. The library exists because five projects were each writing the same pieces
on their own and drifting apart. A new component hand-written in the consuming
project reintroduces exactly that problem.

Do not hand-write colors, sizes or spacing either. Every value in the system has
a token and a Tailwind utility; a `#hex` or a `p-[13px]` in the consuming project
is the sign that the wrong path was taken.

## Installation

```bash
pnpm add @eduardoalvarez/arrecife
```

Requirements, and they are not optional:

| | |
| --- | --- |
| React | `^19.0.0` and `react-dom` `^19.0.0`, as peer dependencies |
| Tailwind | v4. **There is no v3 preset**: the output is `@theme`, which v3 does not understand |
| Node | `>=22.18.0` for the subpaths that run at build time (`./og`, `./tokens`) |

Radix, `clsx`, `tailwind-merge`, `class-variance-authority`, `date-fns` and
`react-day-picker` come as dependencies of the library. You do not need to
install or declare them.

**It ships no `lucide-react` and no icon library.** The glyphs the components
need are inline, inherit `currentColor` and measure 1em.

## Tailwind configuration

Two lines, in this order, in the project's entry stylesheet:

```css
@import "tailwindcss";
@import "@eduardoalvarez/arrecife/tokens/theme.css";
```

Without the second one, the components mount with none of the system's styles:
the classes they use (`bg-surface-raised`, `text-h1`, `rounded-card`) do not
exist in a bare Tailwind.

Tailwind has to scan the library so it does not purge those classes. If the
project declares `@source`, include the package:

```css
@source "../node_modules/@eduardoalvarez/arrecife/dist";
```

### Light mode and dark mode

**Dark mode is primary and it is the default.** A dark project declares nothing.
A project in light mode declares the attribute on `<html>`:

```html
<html data-theme="light">
```

There is no `dark:` class. The variant available is `light:`, for the cases of
inverted light mode, and it is almost never needed: the tokens already switch on
their own.

### Fonts

The library declares the families **by name** and does not load them. The project
loads Bricolage Grotesque (`font-display`), Geist (`font-sans`) and JetBrains
Mono (`font-mono`) however it prefers — `next/font`, `@fontsource`, a `<link>`.
If it does not load them, the browser falls back and the typography looks wrong.

The name has to match **exactly** the one the tokens declare, and this has
already failed in two projects:

| Utility | Name the token asks for |
| --- | --- |
| `font-display` | `"Bricolage Grotesque"` |
| `font-sans` | `"Geist"` |
| `font-mono` | `"JetBrains Mono"` |

Several font packages publish them as `"Bricolage Grotesque Variable"` or
`"Geist Variable"`. Registering the `@font-face` under that name does NOT load
what the tokens ask for: the family falls back to the system silently, with no
console error. The `@font-face`'s `font-family` is an alias the project chooses,
so write it with the name from the table.

## What to import from where

The choice matters, for two different reasons. Four subpaths **do not drag React
in**, so they can be consumed from a worker, an `astro.config.mjs`, a build
script or a Satori generator. Another two ask for an **optional peer dependency**
that only whoever uses them installs.

| Subpath | Drags React | Also requires | What for |
| --- | --- | --- | --- |
| `@eduardoalvarez/arrecife` | yes | — | Components, primitives, brand, `cn`. Re-exports tokens and theme |
| `@eduardoalvarez/arrecife/tokens` | **no** | — | The `tokens` object in JS. Satori, Astro, scripts |
| `@eduardoalvarez/arrecife/tokens/theme.css` | — | — | Tailwind v4's `@theme` |
| `@eduardoalvarez/arrecife/theme` | **no** | — | `themeScript` for the `<head>`, and reading or changing the mode |
| `@eduardoalvarez/arrecife/variants` | **no** | — | The class vocabulary: `buttonVariants`, `badgeVariants`, `CARD_SURFACE` |
| `@eduardoalvarez/arrecife/og` | **no** | — | The Open Graph templates for Satori |
| `@eduardoalvarez/arrecife/shiki` | **no** | — | The syntax highlighting theme |
| `@eduardoalvarez/arrecife/brand` | yes | — | Logo, isotype and mascot as components |
| `@eduardoalvarez/arrecife/form` | yes | `react-hook-form` | The form layer: labels, errors and `aria-*` |
| `@eduardoalvarez/arrecife/chart` | yes | `recharts` | The chart chassis and the series palette |
| `@eduardoalvarez/arrecife/assets/*` | — | — | The brand PNGs |

Importing the root from a build script to get one token is the mistake the
subpaths exist to prevent: it drags all of React into a worker that never mounts
it.

`./form` and `./chart` sit outside the root for the symmetric reason: if they
hung off the main index, the projects that draw no charts and use no React Hook
Form would have to install those dependencies anyway so their bundler could
resolve an import they never execute.

### Next, Server Components and `"use client"`

The root, `./brand`, `./form` and `./chart` ship `"use client"` in the published
`dist/`. They render React and their Radix primitives call `createContext` at
module scope, so without the directive a Next project with the App Router cannot
import them at all: it fails at build time with
`TypeError: (0 , r.createContext) is not a function`.

You do not add anything: importing `Button` from a Server Component works, and
the boundary is already where it belongs. What you should NOT do is wrap the
import in an adapter of your own marked `"use client"` — that was the workaround
before 0.7.0 and it pulled 272 KB of client chunk in for components that never
needed it.

The five portable subpaths do NOT carry the directive, and that is the half that
matters in a Server Component: `./tokens`, `./theme`, `./variants`, `./og` and
`./shiki` stay on the server. If all you need are classes — for a `<div>`, an
`<a>` or an Astro island you do not want to hydrate — import them from
`./variants` and nothing crosses to the client:

```tsx
// A Server Component, or an .astro frontmatter. No React reaches the browser.
import { buttonVariants, CARD_SURFACE } from '@eduardoalvarez/arrecife/variants';

<a className={buttonVariants({ variant: 'tertiary' })} href="/cursos">./ver_cursos →</a>
<div className={CARD_SURFACE}>…</div>
```

In Astro and in plain Vite the directive is inert — a string literal at the top
of a module. Rollup may warn `Module level directives cause errors when bundled`
and nothing else happens: one `dist` serves the Next projects and the Astro ones.

```ts
// Good, in an OG generator or in astro.config.mjs
import { tokens } from '@eduardoalvarez/arrecife/tokens';
import { arrecife } from '@eduardoalvarez/arrecife/shiki';

// Good, in the <head> of an Astro that mounts no React
import { themeScript } from '@eduardoalvarez/arrecife/theme';

// Bad: mounts React where it is not needed
import { tokens } from '@eduardoalvarez/arrecife';
```

### The theme, and the first-paint flash

`ThemeToggle` is the button; the hard part is in `./theme`. Without `themeScript`
inline in the `<head>`, the first paint comes out in the default mode and the
chosen one arrives a frame later: on a dark site the user left in light mode,
that is a white flash on every load.

```astro
---
import { themeScript } from '@eduardoalvarez/arrecife/theme';
---
<head>
  <!-- The site follows the reader's OS, falling back to dark. -->
  <script is:inline set:html={themeScript()} />

  <!-- Or: this site IS dark, and the OS is not consulted. -->
  <script is:inline set:html={themeScript({ base: 'dark' })} />
</head>
```

`base` is not «the fallback», it is «this site IS this mode». A stored choice
still wins over it, so the toggle keeps working — it sets what happens when
nobody has chosen yet. Use it when the project has already decided its mode and
does not want the OS overruling that.

It has to go INLINE. A `<script src>`, even a synchronous one, gets downloaded,
and the flash comes back. The script re-attaches on `astro:after-swap` because
view transitions replace the whole `<html>`.

### The social icons are namespaced

```tsx
// ❌ does not exist
import { GitHub } from '@eduardoalvarez/arrecife';

// ✅
import { social } from '@eduardoalvarez/arrecife';
<social.GitHub />
```

All nine: `GitHub`, `LinkedIn`, `X`, `Instagram`, `Discord`, `YouTube`, `Rss`,
`Email`, `Newsletter`. They live under a namespace because one of them is called
`X`, and loose it collides. `Newsletter` is the bell: a way to follow, like
`Rss`, named for what it means.

The internal glyphs — `Close`, `ChevronDown`, `Sun` — are **not exported** and
are not going to be: they are the primitives' minimum set. A component that needs
an icon receives it as a prop (`Stat` has `icon`, each `SocialLink` in `Footer`
has its own). Do not ask for them to be published: pass your own.

## Tokens

The source is a TypeScript object and the CSS output is generated from it, so the
same value is available in both places and they cannot disagree.

| Token | Custom property | Tailwind utility |
| --- | --- | --- |
| `colors[mode].surfaceRaised` | `--color-surface-raised` | `bg-surface-raised` |
| `brand.hull` | `--color-brand-hull` | `bg-brand-hull` |
| `typeScale.h1` | `--text-h1` | `text-h1` (brings line-height, weight and tracking) |
| `fonts.display` | `--font-display` | `font-display` |
| `radius.card` | `--radius-card` | `rounded-card` |
| `spacing.stepLg` | `--spacing-step-lg` | `p-step-lg`, `gap-step-lg`, `mb-step-lg` |
| `spacing.section` | `--spacing-section` | `py-section`, `mb-section` |
| `control.md` | `--spacing-control-md` | `px-control-md` |
| `control.icon` | `--spacing-control-icon` | `size-control-icon` (42×42) |
| `gradient[mode].hero` | `--gradient-hero` | `gradient-hero` |
| `size.nav` | `--spacing-nav` | `h-nav` |
| `size.content` / `size.wide` | `--container-content` / `--container-wide` | `max-w-content` / `max-w-wide` |
| `limits.measure` | `--container-measure` | `max-w-measure` |
| `shadow.standard` | `--shadow-standard` | `shadow-standard` |
| `motion` | `--duration-standard`, `--ease-standard` | `duration-standard`, `ease-standard` |

`transition-standard` is the system's only transition and it can only animate
color and border: that is how the utility is written.

**The spacing steps carry `step` in the name and it is not optional.** `p-md` is
not an Arrecife class: in a Tailwind v4 project it lands on the numeric scale and
does nothing visible. Page rhythm is `p-step-md`, `gap-step-sm`, `py-step-xl`.
They carry a prefix because `xs, sm, md, lg, xl` are the names of Tailwind's
`--container-*` scale, and a `--spacing-md` of our own was swallowing `max-w-md`
across the whole project with nothing warning about it. `max-w-*`, `w-*` and
`h-*` belong to Tailwind and are used as they are. Migration guide from 0.2.0:
<https://github.com/Proskynete/arrecife/blob/main/docs/migration-0.3.md>.

## System rules the consuming code must not break

These are identity decisions, already measured. Breaking them produces code that
compiles and looks wrong, or that fails the project's accessibility audit.

1. **Zero literal hexes.** Every color comes from a token or its custom property.
2. **`Button variant="conversion"` appears once per screen.** It is not enforced
   at runtime; two on the same page are a design error.
3. **`Button variant="destructive"` is for the irreversible only.** Never for
   «cancel» on a form, and not inside an `AlertDialog` — there the confirm button
   stays `primary`, because the title, the focus on cancel and the no-click-outside
   already carry the weight. See `docs/decisions.md` § 21.
4. **`secondary` is never filled.** It is border and text.
5. **No entrance animations.** Modals, menus, tooltips and toasts appear where
   they will stay. The only exception is the `Button loading` spinner.
6. **Semantics and scale are independent.** An `h2` that has to look small is
   `<Text as="h2" variant="h3">`, never an `h3` that lies about the hierarchy.
7. **`textMuted` never goes over `surfaceRaised`**: it gives 4.07 in dark. Over a
   raised surface — menus, active tabs — the token is `textSecondary`.
8. **A background tinted with a semantic color carries text from a text token**,
   not from the semantic color. The color stays on the border and on the glyph.
   Putting `accent` over its own tint at 8 % gives 4.12 and does not reach AA.
9. **`Progress` requires `label`.** A bar with no accessible name does not say
   what it is about.
10. **`Button size="icon"` and `size="icon-sm"` require `aria-label`.** They carry
    no text. `icon` is 42×42 and is a page action; `icon-sm` is 32×32 and is for a
    dense table row.
11. **The mascot's faces only appear** in empty states, confirmations, errors,
    course progress and celebration. Never in a hero, pricing, services, contact
    or the CV.
12. **The fin is not a free parameter**: `foam` on a dark background, `color` on a
    light one. The components already choose it from the background.

## What the library does NOT do, on purpose

These are the confusions people run into most often when consuming it.

- **It does not ship Shiki.** It publishes the *theme*, not the highlighter.
  `CodeBlock` receives the code **already highlighted** by the project's tool.
- **It does not format dates.** `ArticleCard`, `TalkCard` and company receive the
  date already formatted by the project: the library imposes no locale.
  `dateTime` is separate, in ISO, for the `<time>` attribute.
- **`NewsletterForm` does not do the POST.** It is presentational: it takes
  `state` and emits `onSubmitEmail`. The call is made by the project with its own
  provider.
- **It ships no router.** The components with links accept `asChild` to wrap the
  framework's `Link`.
- **It does not load fonts.** It declares them by name.
- **There is no Tailwind v3 preset.**

## Usage patterns

```tsx
import { Text, Button, Badge, cn } from '@eduardoalvarez/arrecife';
import type { TextProps } from '@eduardoalvarez/arrecife';

<Text variant="eyebrow" tone="muted">charlas</Text>
<Text as="h2" variant="h1">Escalar con criterio</Text>
<Text variant="body">Clamps itself to 68ch.</Text>
<Text variant="ui" measure={false}>No clamp, for a narrow cell.</Text>
```

`asChild` renders the child instead of the component's own element. It is how the
framework's link gets wrapped without losing the styles:

```tsx
<Button asChild>
  <Link href="/cursos">Ver los cursos</Link>
</Button>
```

`cn` is `clsx` + `tailwind-merge`. It is used to compose `className` without two
utilities from the same group fighting each other.

Open Graph, without React:

```ts
import satori from 'satori';
import { articleTemplate, OG } from '@eduardoalvarez/arrecife/og';

const svg = await satori(articleTemplate({ title, date, readingMinutes }), {
  width: OG.width,   // 1200
  height: OG.height, // 630
  fonts: [...],
});
```

Syntax highlighting, from the site's configuration:

```ts
import { arrecife } from '@eduardoalvarez/arrecife/shiki';

export default defineConfig({
  markdown: { syntaxHighlight: 'shiki', shikiConfig: { theme: arrecife } },
});
```
